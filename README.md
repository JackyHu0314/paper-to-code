# paper-to-code

一个用于精读机器学习论文与官方代码的 Codex Skill。

它面向这样的阅读场景：你准备在自己的研究里引用一篇论文，但摘要、结论和二手解读还不足以支撑引用。你需要继续往下看，直到能回答：数据到底怎样进入模型？每一维代表什么？关键模块怎样计算？公式落在哪段代码？训练与推理有什么不同？论文的结论由什么证据支持？

`paper-to-code` 会把阅读主线从“论文说了什么”推进到“模型具体怎么算”。

## 它会怎样读一篇论文

- 从一条真实样本、输入和预期输出开始，而不是先堆概念。
- 沿数据流追踪预处理、batch、条件输入、关键层、预测目标和后处理。
- 给出张量 shape，并解释 `B`、`T`、`N`、`D` 等每一维在当前模型中的语义。
- 把投影、卷积、注意力、reshape、拼接、归一化等操作与源码逐段对齐。
- 将核心公式连接到具体变量、shape、计算目标和实现位置。
- 分开讲清训练、损失、梯度路径与推理循环、缓存、后处理。
- 最后再讨论设计理由、替代方案、计算成本和消融证据。

它尤其关注两类常见误读：shape 对得上但维度语义错了，以及 shape 没变但计算含义已经变了。

## 适合什么任务

- 精读一篇即将引用的论文，核实方法细节与证据边界。
- 把论文图、公式和作者官方仓库中的模块对应起来。
- 顺着真实配置确认关键层的输入输出 shape。
- 走通训练与推理的完整数据路径。
- 判断某个设计为什么存在、能否替换，以及替换会影响哪里。

普通摘要、整篇翻译和批量文献整理不会默认展开成这种深度。

## 证据原则

优先级依次是原论文与附录、作者项目页、官方仓库及配置。关键 shape 会标明它来自论文或配置、由已知操作推导，还是实际运行观察。无法确认的维度会保留为符号或明确标成未知，不编造层数、行号、调用关系和运行结果。

如果官方实现缺失，可以做教学重建，但会明确说明假设以及它与论文的差异，不把重建代码称为官方实现或忠实复现。

## 安装

```bash
git clone https://github.com/JackyHu0314/paper-to-code.git ~/.codex/skills/paper-to-code
```

如果该目录已经存在，请先备份或选择其他安装位置，不要直接覆盖现有内容。

## 使用

在 Codex 中直接调用：

```text
$paper-to-code 带我精读这篇论文。我准备在文章里引用它，请从一条具体样本和整体计算图开始，结合官方代码追踪关键模块、每一步 shape、训练与推理差异，并标明每个结论的证据来源。
```

也可以从具体问题切入：

```text
$paper-to-code 解释这一段 cross-attention 在全模型中的位置。请从输入变量开始追踪到输出，列出 reshape、mask 和 attention score 的 shape，并定位官方实现。
```

## 文件

```text
paper-to-code/
├── SKILL.md
└── agents/
    └── openai.yaml
```

`SKILL.md` 是完整教学与证据规范；`agents/openai.yaml` 提供 Codex 中的显示名称、简介和默认提示词。
